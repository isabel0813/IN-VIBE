# 바꿔도 돼? · Frontend

React + Vite + TypeScript 웹앱과 Phase 2의 Tauri 2 Windows 앱입니다. 기존 FastAPI를 사용하며 별도 프론트엔드 서버 저장소나 로그인은 없습니다. 데스크톱 실행·위젯 구조·검증 범위는 [데스크톱 안내](docs/desktop.md)를 참고하세요.

## 실행

Node.js 24 LTS 환경에서 검증했습니다.

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

브라우저에서 터미널에 표시된 주소(기본 `http://127.0.0.1:5173`)를 엽니다. macOS/Linux에서는 `npm.cmd` 대신 `npm`을 사용합니다. Windows에서 PowerShell 실행 정책으로 `npm.ps1`이 차단될 때도 `npm.cmd`로 실행할 수 있습니다.

백엔드는 별도 터미널에서 [기존 실행 안내](../backend/README.md)에 따라 `--port 8010`으로 실행합니다. Windows의 8000 포트 충돌을 피하도록 기본 연결 주소는 `http://127.0.0.1:8010`입니다. 백엔드 주소를 바꾸려면 `.env.example`을 `.env.local`로 복사해 수정한 뒤 Vite를 재시작합니다. `.env.local`은 Git에서 제외됩니다. Windows Python에는 `tzdata`가 필요합니다(백엔드 의존성 목록 반영은 백엔드 담당자와 협의).

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:8010
```

`VITE_` 환경변수는 클라이언트 번들에 포함됩니다. 비밀 키를 넣지 마세요. 다른 기기에서 접속할 때에는 해당 기기에서 접근 가능한 백엔드 주소와 백엔드 `CORS_ORIGINS` 설정이 필요합니다. 빌드 후에는 환경변수 변경 시 다시 빌드해야 합니다.

## 사용 흐름

1. 여러 할 일을 자연어로 적고 **AI로 할 일 정리**를 누릅니다.
2. AI의 추정 내용을 읽고 이름, 마감, 예상 시간, 중요도를 수정합니다. 초안은 확인 후 저장됩니다.
3. **저장하고 계획 보기**를 누르면 백엔드가 계산한 작업 순서, 지금 할 일, 여유 시간, 부족 시간을 표시합니다.
4. **작업 시작**으로 집중 상태를 표시하고, 완료 버튼이나 체크박스로 작업을 완료합니다. 완료 체크를 해제하면 계획에 다시 포함됩니다.

AI 오류(422/503), Ollama 미실행, 네트워크 오류 시 직접 입력 폼으로 전환됩니다. AI 응답 대기 중에도 직접 입력을 선택할 수 있습니다. 원문은 확인 화면에서 펼쳐 볼 수 있습니다. 직접 입력에는 AI가 필요 없지만, **저장과 계획 계산에는 FastAPI 연결이 필요합니다**. 실패한 저장은 초안을 유지하며, 성공한 저장 이후 조회만 실패한 경우에는 다시 연결할 때 중복 저장하지 않습니다.

## API 계약

| API                 | 용도                                             |
| ------------------- | ------------------------------------------------ |
| `POST /tasks/parse` | `{ text }` → `{ drafts, assumptions }`           |
| `POST /tasks/batch` | `{ tasks: TaskDraft[] }` → 생성된 작업 배열      |
| `GET /tasks`        | 완료한 작업을 포함한 목록                        |
| `PATCH /tasks/{id}` | 작업 정보 수정 또는 `{ done: boolean }`          |
| `GET /plan`         | 작업 순서, 지금 할 일, 여유·부족 시간, 지난 마감 |
| `GET /settings`     | 내일 이후 계산에 쓰는 `daily_minutes` 읽기       |

- 첫 요청에서 UUID를 생성하고 `localStorage`의 `in-vibe.user-id`에 저장합니다. 모든 요청에 동일한 `X-User-Id`를 보냅니다. 저장소를 지우거나 브라우저/접속 origin을 바꾸면 별도 사용자로 처리됩니다.
- 날짜 입력과 표시는 한국 시간(Asia/Seoul)입니다. 저장할 때 ISO 8601의 `+09:00`을 명시합니다.
- 서버 제약과 동일하게 작업 이름 1~100자, 예상 시간 5~6000분(정수), 일괄 등록 1~30개, 자연어 입력 2000자를 적용합니다.
- 계획 계산은 서버가 담당합니다. `free_minutes: null`, `now_task: null`, 지난 마감, 시간 부족, 빈 목록을 구분합니다. 지난 마감은 부족 시간 합산에 넣지 않습니다.
- 계획 화면은 1분마다, 창에 다시 포커스가 올 때, 저장·완료 변경 후 갱신합니다. 조회 실패 시 오래된 계획 대신 연결 안내를 표시합니다.
- 일반 요청은 15초, AI 파싱은 기본 Ollama 준비 시간을 고려해 130초까지 기다립니다. 백엔드 작업이 이미 처리된 후 응답만 끊긴 경우에는 자동 재전송하지 않습니다. 저장 응답이 시간 초과되었다면 재저장 전 나의 계획에서 저장 여부를 확인하세요.

## 코드 구조

```text
src/
  api/          # HTTP, 사용자 UUID, FastAPI 요청·응답 타입
  components/   # 초안 편집기, 계획 화면, 아이콘
  lib/          # 한국 시간 변환, 초안 검증·직렬화
  test/         # 테스트 공통 설정
  App.tsx       # 입력 → 확인 → 계획 상태와 데이터 갱신
  styles.css    # 노트북 우선 다크 테마와 작은 화면 대응
```

UI와 HTTP 코드를 분리했습니다. 데스크톱에서는 `작업 시작` 시 독립 안뇽이 위젯을 표시하고 메인 창을 숨깁니다. Rust 메모리에서 세션을 공유하며 앱 재시작 후에는 자동 재개하지 않습니다. 웹에서는 OS 창 제어 없는 미리보기를 제공합니다. 실제 활동 감지, 딴짓 시간 측정, 계획 복구 이벤트는 Phase 3 범위입니다.

## 검증

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run preview
```

Vitest + Testing Library로 실제 HTTP 클라이언트를 사용하고 `fetch` 응답을 테스트 안에서 대체합니다. UUID, 6개 API의 경로·본문·헤더, 한국 시간, 입력 제한, AI 성공/실패/대기 취소, 저장 재시도, 저장 후 조회 실패, 작업 시작·완료·복원·수정, 지난 마감·부족 시간 표시를 검증합니다. 테스트 응답은 앱 실행 코드에 포함되지 않습니다. 이 테스트는 실제 Ollama 모델 출력이나 실서버 E2E 검증을 대체하지 않습니다.
