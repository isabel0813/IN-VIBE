# 뭐보뇽 한 줄 집중 흐름 통합 — 2026-11-15

기준 커밋 `feat/landing-c`의 `bb22cdd`. 별도 브랜치 `feat/unified-focus-flow`에서 작업했다.
2026-11-12 기획에 맞춰 기존 세션 흐름을 C안에 연결했으며 새 개입 UX는 추가하지 않았다.

## 구현

- C안의 네이비 배경·캐릭터·세로 배치를 유지하고, 입력을 1~100자의 한 줄과 `집중 시작` 버튼으로 변경했다.
- `CloudSession.tsx`의 기존 시작/종료/AI 판단 코드를 `useCloudController`로 추출했다. 메인 `App`에 한 번만 마운트하며 화면 전환 중에도 유지한다.
- `POST /sessions` 성공 후 기존 `sessionStore`에 서버 작업명을 전달한다. 서버 ID는 기존 방식대로 로컬 task ID에 오프셋을 더해 연결한다. API 계약은 변경하지 않았다.
- Tauri `widget_show(hideMain: true)`를 그대로 사용한다. 웹은 기존 위젯 미리보기를 사용한다.
- 진행 중이거나 시작 요청 중인 세션의 중복 생성을 막는다. 위젯 표시 실패 후에는 표시만 재시도하고 `/sessions`를 다시 호출하지 않는다.
- 위젯의 `집중 화면 보기`/`할 일 입력하기`는 기존 native input/plan 메시지를 사용하지만 새 메인에서는 집중 화면으로 돌아온다. 이 복귀에는 작업·계획 API를 호출하지 않는다.
- 위젯 종료는 기존 공유 스토어를 종료한다. 메인 컨트롤러가 이를 감지해 같은 서버 세션을 종료하며 클라우드 질문·세션 캐시를 지운다. 메인에서 종료할 때도 같은 기존 종료 동작을 사용한다.
- AI 동의는 기본 꺼짐이고 세션 시작으로 변경되지 않는다. 설정을 왕복해도 컨트롤러가 유지되므로 동의와 영상 판단 캐시가 초기화되지 않는다. Windows/YouTube 동의 검사는 기존 Rust 및 확장 로직을 그대로 사용한다.
- 기존 작업 화면은 `LegacyPlanner.tsx`로 보존했다. 설정에서 명시적으로 `기존 작업 보기`를 선택한 경우에만 로딩·조회한다. 기본 흐름에서는 `/tasks`, `/tasks/parse`, `/plan`, `/settings`, `/plan/wasted`를 호출하지 않는다.
- 기존 작업 화면이 열려도 두 번째 클라우드 세션 컨트롤러나 웹 위젯을 마운트하지 않는다. 세션 실행 중에는 기존 작업 화면 진입을 막는다.

## 보존 범위

백엔드 소스·API·데이터, Chrome 확장·Native Messaging, Windows 감지, 영상 판단/오탐 정정/동일 영상 재질문 방지, 기존 복귀 측정·복구 로직은 삭제하지 않았다.
기존 `App`의 작업 화면 테스트는 `LegacyPlanner.test.tsx`로 옮겨 계속 실행한다. 기존 `CloudSession`의 미커밋 리뷰 수정(늦은 응답 처리, 관측 오류 처리, 종료 실패 처리, 정정 잠금)도 유지했다.
작업 전 로컬 diff와 CloudSession 파일은 무시되는 `.qa/session-flow-baseline/`에 백업했다.
`browser.rs`와 `docs/mvp-integration-review.md`의 기존 미커밋 변경은 이번 작업에서 수정하지 않았다.
커밋에는 한 줄 집중 흐름 연결에 필요한 변경만 포함한다. CloudSession의 이전 리뷰 보완과 관련 테스트는 작업 트리에 보존하며, 아래 테스트·실행 결과는 그 보완도 포함된 작업 트리를 대상으로 얻은 결과다.

## 자동 검증

- React: 12개 파일, 90개 테스트 통과.
- Chrome 확장: 8개 테스트 통과.
- React TypeScript/Vite 빌드: 통과. 기존 작업 화면은 별도 지연 로딩 청크로 출력.
- Tauri `cargo check --offline`: 통과.
- Rust 테스트: 20개 통과. 동의 없을 때/일시정지/종료 상태의 감지 차단 테스트 포함.
- Windows release 앱 빌드: `npm.cmd run desktop:build -- --no-bundle` 통과. NSIS 설치 프로그램은 이번에 만들지 않음.
- 생성 파일: `frontend/src-tauri/target/release/in-vibe.exe` (8,977,408바이트, 아래 최종 재빌드 후 크기는 달라질 수 있음).
- 기존 증분 캐시 hard-link 실패 시 복사로 대체하는 경고가 있었으며 컴파일은 성공했다.

## 실제 Windows 확인

실행 중인 debug Tauri 앱과 Vite의 현재 프론트엔드에서 아래를 확인했다. 새 release 바이너리를 실행한 검증과는 구분한다.

1. C안에서 `[통합 검증] 전자기 유도 공부` 한 줄 입력.
2. 감지/AI 동의 없이 집중 시작.
3. 메인 창 숨김, 독립 안뇽이 위젯의 `집중 중` 상태 확인.
4. 말풍선에서 같은 작업명 확인.
5. 위젯에서 집중 화면으로 복귀해 같은 작업명 확인.
6. 설정 진입 가능, Windows 활동 감지 `꺼짐` 확인. 동의를 변경하지 않고 집중 화면으로 복귀.
7. 위젯으로 돌아가기 실행 후 위젯의 `집중 세션 종료` 클릭.
8. 메인에서 다시 입력/시작 가능, 위젯은 `작업 대기` 상태 확인.
9. 로컬 DB를 읽기 전용으로 조회해 이 합성 작업의 서버 세션이 정확히 1개이고 `ended_at`이 있으며 `end_reason=stopped`인 것을 확인.

이 테스트는 기존 사용자 작업을 수정하지 않았다. 종료된 합성 테스트 세션 기록은 로컬 DB에 남긴다.

## 미검증 및 후속 범위

- 실제 Chrome 관측→AI 판단→오탐 정정 전체 흐름은 이번에 실행하지 않았다. 회귀 자동 테스트와 기존 코드 보존을 확인한 범위다.
- 활동 수집/AI 동의를 새로 켜지 않았고 확장 재설치·레지스트리 변경을 하지 않았다.
- 새 release 실행 파일의 GUI·설치, 다중 모니터/DPI는 미검증이다.
- API 타임아웃 후 서버에서 처리됐는지는 클라이언트만으로 확정할 수 없다. 자동 생성 재시도는 하지 않는다.
- 기존 통합 리뷰의 미해결 사항을 이번 작업으로 해결했다고 주장하지 않는다.
- push, main 병합, Release 게시, 배포는 수행하지 않는다.
