# Windows MVP: 활동 확인과 계획 복구

기존 React 입력·계획 화면과 독립 80px 안뇽이 위젯을 유지합니다. 백엔드 소스는 수정하지 않습니다.

## 실행 환경

- FastAPI 주소: `http://127.0.0.1:8010`. `.env.local`로 덮어쓸 수 있으며 이 파일은 Git 제외 대상입니다. Tauri CSP도 같은 주소를 허용해야 합니다.
- `npm.cmd run desktop:dev`: Vite 5173과 Tauri를 함께 실행합니다. 기존 서버를 종료할 때는 명령줄·실행 경로가 이 프로젝트인지 먼저 확인하세요.
- Vite 감시에서 `.tools`, `src-tauri/target`, `src-tauri/gen`, `.qa`, `.venv`를 제외합니다.
- Windows Python에는 `tzdata`가 필요합니다. 현재 가상환경에는 설치되어 있습니다. 백엔드 의존성 목록 반영은 백엔드 담당자가 결정해야 합니다.
- `npm.cmd run desktop:build -- --debug --no-bundle`: Windows 실행 파일 생성. `npm.cmd run desktop:build`: release 실행 파일과 NSIS 설치 프로그램 생성.
- NSIS 도구는 `bundle.useLocalToolsDir: true`로 프로젝트의 무시된 `target/.tauri`에 캐시합니다. 사용자 전역 캐시의 압축 해제 접근 거부 오류를 이 방식으로 해결했으며 시스템 권한은 변경하지 않았습니다.

## 동의와 분류

메인 화면의 **Windows 활동 감지**를 펼쳐 수집 범위를 읽고 동의한 뒤 설정을 적용합니다. 동의는 저장하지 않으며 앱 재시작 시 꺼집니다. 집중 세션이 실행 중이고 일시정지가 아닐 때만 Rust가 약 1초 간격으로 읽습니다.

사용하는 Win32 API는 `GetForegroundWindow`, `GetWindowTextW`, `GetWindowThreadProcessId`, `QueryFullProcessImageNameW`, `GetLastInputInfo`입니다. 마지막 API는 마지막 입력의 시각만 반환합니다. 키보드 훅, 입력 내용 기록, 화면 캡처는 없습니다. 창 제목·프로세스·사용자 정정은 로컬 메모리에만 있으며 네트워크 요청이나 로그에 넣지 않습니다. 감지 중지 시 관측 정보와 정정을 지웁니다.

분류 순서:

1. 60초 이상 입력이 없으면 **유휴**. 창 정보는 읽지 않습니다.
2. 사용자가 정상 공부로 정정한 정확한 프로세스+제목, 앱 자체, 사용자가 지정한 관련 단어는 **관련 활동**.
3. 지정한 이탈 의심 단어 또는 일부 명시적 게임 실행 파일은 **이탈 의심**.
4. 그 외는 **미분류**. Chrome, 영상이나 브라우저 자체를 이탈로 판단하지 않습니다.

관련 단어는 의심 단어보다 우선합니다. URL, 페이지 본문, 브라우저 방문 이력은 읽지 않습니다. 입력 없는 영상 강의도 유휴가 될 수 있고, 창 제목이 바뀌면 연속 관측은 다시 시작됩니다. 이는 사용자의 의도를 판정하는 모델이 아닌 보수적인 규칙 기반 MVP입니다.

## 측정과 확인

기본 기준은 같은 의심 창의 연속 관측 300초입니다. Rust release는 300초 미만을 거부하고 개발 빌드에서만 10초까지 설정할 수 있습니다. 2.5초를 초과하는 샘플 공백, 창 전환, 읽기 오류, 유휴는 의심 연속 구간을 끊습니다. `Instant` 기준 경과 시간을 사용해 시스템 시간 변경으로 부풀리지 않습니다.

기준에 도달하면 표정만 `suspect`로 바꿉니다. 자동 말풍선, 자동 창 표시, 포커스 요청은 없습니다. 하나의 확인만 대기하며 그때의 관측 구간을 고정합니다. 클릭할 때까지 지난 시간을 딴짓으로 자동 가산하지 않습니다. 사용자가 위젯을 클릭하면 `checkin`으로 바뀌고 실제 관측 초 수를 보여줍니다.

- **아니, 공부 중이었어**: 서버 호출 없이 같은 프로세스+정확한 제목을 이번 세션에서 관련 활동으로 정정합니다.
- **잠깐 쉬는 중이야**: 세션을 일시정지하고 감지를 중단합니다.
- **맞아, 딴짓했어**: 실제 이탈 시간을 분 단위로 확인·수정합니다. 관측 시간의 분 미만은 기본값에서 제외합니다. 개발 10초 관측의 기본값은 0분이며 1분으로 부풀리지 않습니다.
- 확인 후에는 5분간 재알림을 막습니다. 새 세션에는 이전 정정이나 대기 확인을 적용하지 않습니다.

## 복구 API와 중복 방지

위젯도 메인 창과 같은 WebView origin의 `X-User-Id`를 사용합니다. `/plan/wasted` 본문에는 `wasted_minutes`만 전달합니다. 프로세스, 제목, 관측 시각, 작업 완료 ID는 보내지 않습니다.

기존 `wasted_preview`는 `now - wasted_minutes`의 과거 계획과 `now`의 현재 계획을 비교합니다. 따라서 클라이언트는 `now`를 앞으로 옮기거나 남은 시간에서 이탈 시간을 다시 빼지 않습니다. 서버 현재 시각을 쓰도록 `now`도 생략합니다. 반환한 `plan`과 `impacts`를 그대로 보여주고 다음 할 일로 집중을 시작할 수 있습니다.

Rust에서 확인 ID를 먼저 예약한 뒤 한 번 전송합니다. 더블 클릭, 다른 창, React 재마운트로 재전송할 수 없습니다. 서버에 idempotency 계약이 없으므로 시간 초과/네트워크 오류 후 자동 재시도하지 않습니다. 이 경우 처리 여부는 알 수 없으며 **계획 보기**에서 현재 계획을 확인하고 **확인 마치기**로 닫습니다. 재시작 후 세션·동의·대기 확인을 자동 복원하지 않습니다.

개발용 표정 시뮬레이션은 측정된 이탈과 구분하며 API를 호출하지 않습니다. 웹 모드에는 네이티브 감지 설정이 표시되지 않습니다.

## 검증 명령

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run desktop:check
npm.cmd run desktop:test
npm.cmd run desktop:build -- --debug --no-bundle
node scripts/check-api.mjs
```

`check-api.mjs`는 실행 중인 FastAPI에 새로운 테스트 전용 UUID로 접근합니다. 생성한 테스트 작업만 삭제하며 기존 사용자의 작업은 건드리지 않습니다. 고해성사 테스트 이벤트는 테스트 UUID 아래에 남습니다. 고정 현재 시각 비교로 경과 시간 이중 차감을 검증하고, 별도 요청으로 서버 현재 시각도 확인합니다.

사용자가 실제 감지 테스트에 동의한 뒤 진행했습니다. Computer Use 도구가 테스트용 메모장 접근을 `Computer Use was not approved to use 메모장`으로 거부하여 해당 창 입력을 우회하지 않았습니다. 그래서 5분 연속 의심 관측부터 복구까지의 실제 GUI 검증을 완료라고 하지 않습니다. 테스트 후 감지를 껐고, GUI 테스트 작업은 완료 처리했습니다.

초기 캐릭터 전체 영역 드래그는 자동 조작으로 확실한 이동을 입증하지 못해, 클릭과 충돌하지 않는 하단의 작은 네이티브 이동 손잡이를 추가했습니다. 손잡이 이동 후 말풍선 클릭도 확인했습니다. 창 이동 구현의 기준은 [Tauri 창 사용자 지정 문서](https://tauri.app/learn/window-customization/)입니다.

생성된 파일:

- `src-tauri/target/release/in-vibe.exe`
- `src-tauri/target/release/bundle/nsis/IN-VIBE_0.2.0_x64-setup.exe` (2,018,586 bytes)

빌드 산출물, `.env.local`, `.tools`, `.qa`는 Git에 포함하지 않습니다. 실행 파일은 백엔드가 8010에서 실행 중이어야 저장·계획 기능을 사용할 수 있습니다.

후속 수동 확인: 테스트용 메모장을 의심 단어로 지정 → 동의 후 세션 시작 → 입력을 유지하며 5분 관측(개발 실행에서는 10초 설정 가능) → 표정만 바뀌는지/타 앱 포커스가 유지되는지 확인 → 위젯 클릭 → 정상 공부 정정 또는 실제 이탈 분 수정 → 복구 결과·다음 할 일 확인 → 감지 중지. 배포 전 설치·제거, 서명, 여러 모니터와 배율, 장시간 오탐 빈도도 확인해야 합니다.
