# Windows NSIS Native Host 자동 등록과 복구

사용자별 NSIS 설치는 현재 Windows 사용자의 Chrome Native Host 등록을 설정합니다. 신규 등록에는 Chrome 웹스토어 확장 ID를 사용합니다. 이미 웹스토어판 또는 동봉 개발용 확장이 올바르게 등록돼 있으면 같은 ID 하나를 유지합니다. Chrome 확장 설치는 별도로 진행합니다.

## 자동 복구 조건

- 기존 등록이 로컬 고정 드라이브의 제품 매니페스트를 가리켜야 합니다. 표준 위치는 `%LOCALAPPDATA%\Mobonyong\NativeHost`의 버전별 폴더입니다. 이전 버전의 관리 폴더 및 프로젝트에서 준비한 `extension\.local\native-host` 등록도 지원합니다.
- 제품 이름과 `stdio` 유형, 제품 설명, 단일 허용 origin을 확인합니다. Host 경로는 같은 폴더의 `in-vibe-native-host.exe` 절대경로여야 합니다. 해시와 확장 ID가 포함된 관리 폴더의 경우, 폴더 이름의 ID와 기존 EXE의 해시도 대조합니다.
- 위 조건이 맞고 Host EXE만 사라졌다면, 설치 파일에 포함된 Host의 SHA-256을 확인하고 기존 등록과 매니페스트를 백업한 뒤 복구합니다. 현재 버전과 해시가 같은 폴더라면 검증한 EXE만 복원하며 기존 매니페스트를 보존합니다.
- 알 수 없는 origin, 중복·예상 밖 매니페스트 필드, 매니페스트 누락, 예상 밖 파일이나 폴더 경로, 상대경로·네트워크 경로·리파스 지점은 자동 등록을 중단합니다. 검증 중 기존 등록이나 매니페스트의 내용이 바뀌어도 중단합니다. 이전 형식의 매니페스트는 구조와 경로를 검증합니다. 예전에 생성된 매니페스트의 원본 바이트를 인증할 별도 서명은 없습니다.

## 설치 결과 확인

설치 상세 화면과 `%LOCALAPPDATA%\Mobonyong\NativeHost\logs\installer-registration-*.log`에서 결과를 확인합니다. 로그 한 줄에는 UTC 시각, `status`(성공·실패), `mode`(신규·업데이트·복구), `origin`(웹스토어·개발용·미확인), `stage`(마지막 검사 단계)가 들어갑니다. 영상 정보와 사용자 경로는 로그에 기록하지 않습니다. 로그 폴더를 만들 수 없거나 PowerShell을 시작할 수 없으면 설치 상세 화면에서 실패를 확인할 수 있습니다.

자동 등록이 실패해도 Windows 앱 설치는 완료됩니다. Chrome 연결이 필요하면 기존 등록 상태를 먼저 확인한 뒤 수동 설치 절차를 사용하세요. [Native Host 수동 설치](./windows-release.md#native-host-고정-경로-설치)
