# C안 기존 기능 연결 검증 — 2026-11-15

브랜치: `feat/landing-c`. 백엔드 소스·API 계약, 위젯·YouTube 감지 로직,
기존 미커밋 리뷰 변경은 수정하지 않았다. 새 PRD 기능은 추가하지 않았다.

## 연결 진단

- 개발 기본값, `.env.local`, 실행 중인 Vite가 제공하는 API 모듈 모두 `http://127.0.0.1:8010`이었다. 포트 불일치는 없었다.
- 실제 로컬 `/health`, `/tasks`, `/plan`, `/settings`: 각각 HTTP 200.
- 웹 개발 origin 두 개(127.0.0.1/localhost:5173), Tauri origin에 대한 CORS preflight: HTTP 200.
- 실행 중 Windows 앱에 이전 연결 오류가 표시되어 있었으나, 재확인 시 오류가 사라지고 이후 `계획 동기화됨`과 실제 저장 성공을 확인했다. 최초 실패 시점의 원인은 확정하지 못했다. 서버 재시작이나 포트 변경은 하지 않았다.
- 실제 `/tasks/parse` 한 번 호출: HTTP 503, `ANTHROPIC_API_KEY` 미설정 응답. AI 분석 성공은 미검증이다.
- 프론트엔드가 해당 503을 네트워크 장애와 구분하고 직접 입력을 안내하도록 수정했다. 기타 제공자 오류를 키 미설정으로 단정하거나 원시 오류 본문을 노출하지 않는다.
- 가상환경에서 FastAPI·uvicorn·tzdata를 확인했고, 기존 requirements.txt에 선언됐지만 빠져 있던 certifi 2026.10.23을 해당 가상환경에 설치했다. 백엔드 소스와 의존성 목록은 변경하지 않았다.
- 실행 순서·8010 포트·재연결·빌드별 API 주소·키를 서버에만 두는 방법은 [README](../README.md)에 정리했다.

## 실제 로컬 API 검증

기존 `scripts/check-api.mjs`를 새 테스트 UUID로 실행했다.
작업 일괄 저장 → 조회 → 계획 → `/plan/wasted` → 완료 PATCH와 계획 반영이 통과했다.
복구 시 경과 시간 중복 차감 없음과 서버 현재 시각 사용도 확인했다.
스크립트가 만든 작업만 삭제했으며 기존 사용자 작업은 수정하지 않았다.

## 실제 Windows 앱에서 확인한 범위

이미 실행 중인 Tauri debug 앱과 5173 Vite를 사용했다. 이번에 Windows 실행 파일을 새로 빌드한 것은 아니다.

1. C안 시작 화면에서 직접 입력 화면 진입.
2. `[로컬 검증] C안 직접 입력` 작업 이름 및 다음 날 마감을 입력하고 저장.
3. 계획에 작업명·마감·예상 시간 표시 확인.
4. 작업 시작 후 메인 창이 창 목록에서 사라지고 독립 `안뇽이` 창이 나타남.
5. 위젯의 집중 상태와 말풍선의 동일한 작업명 확인.
6. 위젯의 계획 보기로 메인 창 복귀 및 집중 상태 확인.
7. 작업 완료 후 메인에 `등록한 일을 모두 마쳤어요`, 위젯에 `작업 완료` 상태 확인.

GUI 테스트 작업은 완료 상태로 앱에 남겼다. Windows 활동 감지와 AI 동의는 켜지 않았다.
날짜 선택 팝업은 자동화 도구의 직접 값 설정이 반영되지 않아 기본 달력의 키보드 선택/Enter로 입력했다.

## 미검증·제한

- 실제 AI 초안 생성과 실제 영상 AI 판단: API 키 미설정으로 미검증.
- Chrome 영상 관측·오탐 정정 실제 통합, 다중 모니터·DPI, 감지 동의 흐름: 이번에 실행하지 않음.
- 한 줄 집중 세션 및 세션 종료·실패 처리: 기존 자동 테스트로 확인. 이번 GUI 검증은 작업 기반 집중 시작/완료 경로다.
- Windows 설치 프로그램 재빌드·설치, 공개 Release, 운영 API·배포는 수행하지 않음.
- 기존 리뷰의 미해결 문제는 별도 `docs/mvp-integration-review.md`에 있으며 이번 연결 작업으로 해결했다고 보지 않는다.
